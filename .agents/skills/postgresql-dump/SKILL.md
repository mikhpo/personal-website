## Предназначение

Создание переносимого логического дампа БД стандартной утилитой pg_dump для разовых операций: копия перед рискованным изменением, перенос между провайдерами, независимая от облака резервная копия. Основной механизм защиты данных — автоматические бэкапы провайдера управляемого кластера; данный скилл — для ручных и ад-hoc случаев.

## Долговечные знания

### Совместимость версий

Версия pg_dump обязана быть не ниже версии сервера (кластера). Проверить:

```bash
pg_dump --version                       # версия клиента
psql … -c "SELECT version();"           # версия сервера
```

Если дефолтный клиент старше сервера — вызвать совместимый бинарник явно. На дистрибутивах Debian/Ubuntu старшая версия лежит в `/usr/lib/postgresql/<N>/bin/pg_dump`; выбрать старшую установленную:

```bash
ls -1d /usr/lib/postgresql/*/bin 2>/dev/null | sort -V | tail -1
```

В других системах (macOS/Homebrew и т. п.) использовать клиент из PATH, если его версия подходит.

### Параметры подключения и аутентификация

Параметры те же, что использует приложение (см. конфигурацию БД проекта / раздел «Настройка базы данных» в README). Утилиты libpq принимают их флагами (`-h`, `-p`, `-U`, `-d`). Аутентификация — двумя способами:

- переменная окружения `PGPASSWORD`;
- файл `~/.pgpass` (постоянная запись, не требуется прокидывать пароль в каждую команду).

### Соглашение об имени файла

`<база>_<дата>.dump`, где дата в формате ISO (`YYYY-MM-DD`). Пример: `personal_website_2026-08-13.dump`. Имя базы берётся из параметров подключения; дата — `$(date +%F)`.

### Назначение флагов

- `-Fc` — custom-формат: компактный, допускает выборочное восстановление и параллельную работу.
- `--no-privileges` — пропустить `GRANT`/`REVOKE`: роли и права источника обычно отсутствуют на целевом кластере.
- `--no-subscriptions` / `--no-publications` — исключить логическую репликацию (не относится к приложению, avoids шума при восстановлении на другом кластере).

## Создание дампа

```bash
export PGPASSWORD='<пароль>'
pg_dump -h <хост> -p <порт> -U <пользователь> -d <база> \
    -Fc --no-privileges --no-subscriptions --no-publications \
    -f personal_website_$(date +%F).dump
```

## Размещение артефакта

Готовый файл размещается там, где хранятся резервные копии — локальное хранилище, объектное хранилище (S3-совместимое) и т. п. Конкретный способ зависит от инфраструктуры и со временем меняется, поэтому он не зафиксирован здесь. Для управляемых кластеров подключение требует SSL — сертификат CA доставляется скриптом `scripts/pgcert.sh` (см. README, раздел «SSL для Managed PostgreSQL»).

## Проверка дампа

```bash
pg_restore -l personal_website_*.dump | head    # состав и размер
```

## Рекомендации

- Снимать дамп при остановленном приложении или в окно минимальной записи, чтобы получить консистентную копию.
- Дамп не заменяет автоматические бэкапы провайдера (PITR), а дополняет их переносимым артефактом.
- Восстановление дампа — см. скилл postgresql-restore.
