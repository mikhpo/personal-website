## Предназначение

Восстановление БД из дампа (созданного скиллом postgresql-dump) на целевом кластере PostgreSQL. Штатное восстановление из целей системы бэкапов выполняется командой `bash scripts/backup.sh restore_db <цель>` (скилл backup-restore) - дамп читается из цели конвейером без выгрузки на диск; данный скилл - разовые операции с файлом дампа.

## Совместимость версий

Версия pg_restore обязана быть не ниже версии сервера (кластера). Проверить:

```bash
pg_restore --version                     # версия клиента
psql … -c "SELECT version();"           # версия сервера
```

Если доступный по умолчанию клиент младше сервера, выбрать совместимый: установить пакет нужной версии либо вызвать нужный бинарник явным путём.

## Параметры подключения и аутентификация

Те же, что использует приложение (см. [docs/deployment/database.md](../../../docs/deployment/database.md), раздел 1). Флаги:

* `-h <хост>` - имя хоста или путь к каталогу unix-сокета;
* `-p <порт>` - порт сервера;
* `-U <пользователь>` - имя пользователя БД;
* `-d <база>` - имя базы данных.

Пароль - через переменную окружения `PGPASSWORD` либо файл `~/.pgpass`.

## Два варианта восстановления

Вариант 1 - база уже существует. Восстановление в существующую базу:

```bash
export PGPASSWORD='<пароль>'
pg_restore -h <хост> -p <порт> -U <пользователь> -d <база> \
    -Fc --no-owner --no-privileges personal_website_2026-08-13.dump
```

Если база не пуста - добавить `--clean --if-exists`, чтобы пересоздать объекты идемпотентно.

Вариант 2 - базу нужно создать. Флаг `--create` создаёт базу с именем из дампа и требует права CREATEDB у подключённого пользователя; если этого права нет, базу необходимо создать заранее и применять вариант 1:

```bash
export PGPASSWORD='<пароль>'
pg_restore -h <хост> -p <порт> -U <пользователь> \
    -Fc --no-owner --no-privileges --create personal_website_2026-08-13.dump
```

## Назначение флагов

* `-Fc` - восстановление из custom-формата.
* `--no-owner` - перенести владение объектами на подключённого пользователя (владелец источника на целевом кластере обычно отсутствует).
* `--no-privileges` - пропустить `GRANT`/`REVOKE` (роли источника отсутствуют).
* `--clean --if-exists` - пересоздать объекты перед загрузкой; `--if-exists` подавляет ошибки «объект не существует». Применять для непустой базы или повторного восстановления.
* `--create` - создать базу с именем из дампа; требует права CREATEDB. Без этого флага восстановление идёт в базу, заданную `-d`.

## Проверка целостности

```bash
psql … -c "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
psql … -c "SELECT count(*) FROM blog_article;"
psql … -c "SELECT app, name FROM django_migrations ORDER BY app, name;"
```

Сравнить счётчики ключевых таблиц и набор применённых миграций с источником.

## Рекомендации

* Перед восстановлением в рабочую базу снять свежий дамп (скилл postgresql-dump) как точку отката.
* Если кластер требует SSL, использовать параметры подключения приложения ([docs/deployment/database.md](../../../docs/deployment/database.md)).
* Дампы системы бэкапов лежат в `${BACKUP_ROOT}/db/` (имена `<база>_<дата>_<время>.dump`) и в `db/` целей бэкапов ([docs/deployment/backups.md](../../../docs/deployment/backups.md)).
