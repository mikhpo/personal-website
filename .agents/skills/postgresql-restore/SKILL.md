## Предназначение

Восстановление БД из дампа (созданного скиллом postgresql-dump или выгруженного из автоматического бэкапа провайдера) на целевом кластере PostgreSQL.

## Долговечные знания

### Совместимость версий

Версия pg_restore обязана быть не ниже версии сервера (кластера). Проверить:

```bash
pg_restore --version                     # версия клиента
psql … -c "SELECT version();"           # версия сервера
```

Если дефолтный клиент старее сервера — вызвать совместимый бинарник явно. На Debian/Ubuntu старшая версия: `/usr/lib/postgresql/<N>/bin/pg_restore`; выбрать старшую установленную:

```bash
ls -1d /usr/lib/postgresql/*/bin 2>/dev/null | sort -V | tail -1
```

### Параметры подключения и аутентификация

Те же, что использует приложение (см. README, раздел «Настройка базы данных»). Флаги `-h`, `-p`, `-U`, `-d`. Аутентификация — `PGPASSWORD` или файл `~/.pgpass`.

### Два варианта восстановления

Порядок зависит от того, существует ли уже целевая база.

Вариант 1 — база существует (типично для управляемых кластеров, где базу создаёт провайдер). Восстановление в существующую базу:

```bash
export PGPASSWORD='<пароль>'
pg_restore -h <хост> -p <порт> -U <пользователь> -d <база> \
    -Fc --no-owner --no-privileges personal_website_2026-08-13.dump
```

Если база не пуста — добавить `--clean --if-exists`, чтобы пересоздать объекты идемпотентно.

Вариант 2 — базу нужно создать. На управляемом кластере без права CREATEDB база создаётся средствами провайдера (консоль/CLI), после чего применяется вариант 1. При наличии права CREATEDB (локальный или самостоятельный PostgreSQL) базу создаёт сама утилита:

```bash
export PGPASSWORD='<пароль>'
pg_restore -h <хост> -p <порт> -U <пользователь> \
    -Fc --no-owner --no-privileges --create personal_website_2026-08-13.dump
```

### Назначение флагов

- `--no-owner` — перенести владение объектами на подключённого пользователя (владелец источника на целевом кластере обычно отсутствует).
- `--no-privileges` — пропустить `GRANT`/`REVOKE` (роли источника отсутствуют).
- `--clean --if-exists` — пересоздать объекты перед загрузкой; `--if-exists` подавляет ошибки «объект не существует». Применять для непустой базы или повторного восстановления.
- `--create` — создать базу с именем из дампа; требует права CREATEDB. На управляемых кластерах обычно недоступно — там база создаётся провайдером.

## Проверка целостности

```bash
psql … -c "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
psql … -c "SELECT count(*) FROM blog_article;"
psql … -c "SELECT app, name FROM django_migrations ORDER BY app, name;"
```

Сравнить счётчики ключевых таблиц и набор применённых миграций с источником.

## Рекомендации

- Перед восстановлением в рабочую базу снять свежий дамп (скилл postgresql-dump) как точку отката.
- Для управляемых кластеров подключение требует SSL — сертификат CA доставляется скриптом `scripts/pgcert.sh`.
- Создание дампа — см. скилл postgresql-dump.
