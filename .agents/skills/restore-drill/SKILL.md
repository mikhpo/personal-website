## Предназначение

Скилл для агента, выполняющего учебное восстановление из бэкапов на тестовом окружении (personal-website-test; прод не трогать). Цель - убедиться, что бэкапы реально восстановимы, не по выводу команд, а по работающему приложению.

Запуск только по явному запросу пользователя: агент не инициирует дрилл самостоятельно. Выполнение самих операций бэкапа и восстановления - скилл backup-restore; проверка настроек бэкапов - скилл backup-audit.

## Порядок

Работа на тестовом сервере из корня рабочей копии. Сверка после каждого шага; операции - скилл backup-restore.

1. развернуть стек тестового окружения (скилл server-setup);
2. восстановить медиа из цели: `restore_media <цель>` - число объектов и суммарный размер совпадают с источником (допуск - служебные файлы ОС, например .DS_Store);
3. восстановить БД из цели: `restore_db <цель>` - счетчики ключевых таблиц и django_migrations совпадают с источником, `/health/` - 200;
4. учебный прогон смены типа хранилища туда-обратно через временную цель ([docs/deployment/backups.md](../../../docs/deployment/backups.md), раздел 7): filesystem -> S3-бакет -> обратно; после каждого переноса сверять число объектов и размеры;
5. итоги дрилла: что проверено, найденные дефекты, время выполнения; дефекты кода оформляются отдельными issue/PR.

## Ограничения

- Прод не трогать: все операции - только на тестовом окружении.
- Деструктивные операции - только с явного разрешения пользователя.
