# Матрица развертывания

Проект настраивается не набором готовых конфигураций, а пятью независимыми параметрами развертывания: способ запуска приложения, размещение базы данных, тип хранилища, вариант прокси, конфигурация бэкапов. Каждый параметр настраивается отдельно, точка сборки - один .env с секциями (см. [.env.example](../../.env.example)). Код приложения по режимам развертывания не ветвится.

Документы по параметрам: [application.md](./application.md), [database.md](./database.md), [storage.md](./storage.md), [proxy.md](./proxy.md), [backups.md](./backups.md).

## 1. Параметры развертывания

| Параметр | Варианты | Переменные .env |
| --- | --- | --- |
| Запуск приложения | Docker Compose / docker run / systemd Gunicorn | DEPLOY_MODE, DJANGO_PORT, GUNICORN_WORKERS |
| База данных | managed-кластер / контейнер compose / systemd на хосте | POSTGRES_*, профиль postgres |
| Хранилище | filesystem / S3 удаленный / MinIO локальный | STORAGE_TYPE, AWS_*, профиль minio |
| Прокси | nginx + certbot в compose / nginx + certbot на хосте | COMPOSE_PROFILES, HTTP_PORT, HTTPS_PORT, ACME_EMAIL |
| Бэкапы | источники x цели (mc:, rclone:), расписание | BACKUP_*, cron/systemd timer |

Бэкапы настраиваются независимо от остальных параметров в любом сценарии.

## 2. Типовые сценарии развертывания

Сценарии описывают продакшен-развертывания; локальная разработка - не сценарий развертывания, ее порядок описан в [README.md](../../README.md).

Сценарии различаются одним вопросом: сколько проектов обслуживает сервер. «Однопроектный сервер» целиком отдан этому сайту. «Сервер с несколькими проектами» обслуживает и другие сайты, поэтому порты 80/443 занимает общий хостовый nginx, а проект занимает в нем свое место. Способ запуска приложения (Compose или systemd) не определяется сценарием и выбирается отдельно в каждом из них.

| Параметр | Однопроектный сервер | Сервер с несколькими проектами |
| --- | --- | --- |
| Запуск приложения | Compose или systemd | Compose или systemd |
| Прокси | прокси проекта: nginx + certbot (в compose или на хосте) | общий хостовый nginx + certbot, конфигурация сайта на проект |
| Публикация приложения | 127.0.0.1:${DJANGO_PORT} | 127.0.0.1:${DJANGO_PORT} или unix-сокет, свободные от других проектов |
| База данных | любой вариант | любой вариант, отдельный на проект |
| Хранилище | любой вариант | любой вариант |
| COMPOSE_PROFILES | по выбранным вариантам БД, хранилища и прокси | по выбранным вариантам БД и хранилища (профиль nginx не используется: 80/443 заняты общим прокси) |

## 3. Чеклисты сценариев

### Однопроектный сервер

1. Выбрать способ запуска: Docker Compose ([application.md](./application.md), раздел 2) или systemd Gunicorn (раздел 4); первичная настройка - scripts/docker/setup.sh или scripts/server/setup.sh;
2. выбрать прокси проекта: контейнер nginx профиля nginx (сертификат выпускается setup.sh standalone до старта стека) или хостовый nginx + certbot ([proxy.md](./proxy.md));
3. `https://<домен>/health/` - 200, сертификат валиден, медиа открываются;
4. бэкапы настроены ([backups.md](./backups.md)): `backup --verify` проходит по всем целям.

### Сервер с несколькими проектами

1. Общий хостовый nginx + certbot: конфигурация сайта проекта по рецепту [proxy.md](./proxy.md) (раздел 2), сертификат certonly webroot; тестовые среды - ACME staging;
2. приложение публикуется на свободном порту 127.0.0.1 или unix-сокете (systemd-режим, [application.md](./application.md), раздел 4);
3. при Compose-запуске `docker compose config` выполняется без предупреждений (валидация сочетания переменных);
4. `/health/` - 200 через сайт проекта; порты и сокеты других проектов не затронуты;
5. бэкапы: цели настроены, `backup --verify` проходит.

## 4. Что поддерживается

- перечисленные варианты пяти параметров и их сочетания в рамках типовых сценариев;
- хостовые скрипты автоматизации повторяющихся шагов (setup, deploy, backup, cronjobs);
- systemd timer как альтернатива cron для расписания бэкапов.
